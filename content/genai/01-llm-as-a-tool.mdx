## このコースの立ち位置

「GPU の使われ方」コースでは、学習したモデルが推論サーバーに載り、API として呼べるようになるまでを見ました。このコースは、その**先**です。API の向こうのモデルを、利用者はどう使い、エンジニアはどう道具にしているのか。

一次情報には、主に Anthropic の Claude のドキュメントを使います。用語集のページ自身が書いているとおり、ここで扱う概念の多くは Claude に固有のものではありません。ただし、**数値（上限や価格）は Claude のもの**で、2026 年 10 月時点の値です。

---

## 次の 1 トークンを予測する

Claude のドキュメントの用語集によると、Claude の土台になっているような言語モデルは、**文書のそれまでの文脈から次の語を予測する**ように事前学習（pretraining）されています。

<Figure name="generation-loop" caption="出したトークンを入力の後ろに足して、もう一度モデルに通す（「GPU の使われ方」コース レッスン 5 の図）" source="Hugging Face Transformers の LLM tutorial を元に作図" />

用語集は、事前学習しただけのモデルは、**質問に答えたり指示に従ったりするのが得意ではない**とも書いています。そこで、追加の学習（ファインチューニング）と、人の評価を使う学習（RLHF）で、アシスタントとして振る舞うように仕上げます。「GPU の使われ方」コース レッスン 4 のファインチューニングは、この仕上げの一種です。

使う側から見ると、**モデルは文脈に続くトークンを順に出している**、と捉えておくのが出発点です。このあとの「ぶれ」は、予測をどれだけランダムに選ぶか（temperature）と関わります。

---

## トークン — モデルが数える単位

用語集によると、**トークン**はモデルが扱う最小の単位で、語・語の一部・文字、さらにはバイトに当たることもあります。Claude では、英語でおよそ **3.5 文字が 1 トークン**ですが、言語によって変わります（用語集の目安。Models overview のページによると、Claude Opus 4.7 から新しいトークナイザになっており、同じ文章のトークン数はモデルの世代でも変わります）。

モデルに渡す文章はトークンの列に変換され、出力もトークンの列として出てきます。利用者からは見えませんが、次の 3 つはトークンで数えられます。

| トークンで数えるもの | どこで効くか |
| --- | --- |
| 1 回の要求で扱える量 | コンテキストウィンドウ（次のスライド） |
| 料金 | 入力と出力のトークン数に単価を掛ける（レッスン 2） |
| 速さ | 出力のトークンは 1 つずつ生成される（「GPU の使われ方」コース レッスン 5） |

## コンテキストウィンドウ — 作業用の記憶

用語集は、**コンテキストウィンドウ**を、モデルが応答を作るときに参照できるテキストの量で、学習に使った大量のデータとは別の**作業用の記憶**だと説明しています。

<Figure name="context-window-contents" caption="1 回の要求で、モデルが参照するもの。出力も同じ枠の中で数える" source="Claude Docs — Context windows を元に作図" />

Context windows のページによると、ウィンドウに数えられるのは次のすべてです。

- システムプロンプト、`messages` のすべて（ツールの結果・画像・文書を含む）、ツールの定義
- その回にモデルが出す出力（拡張思考を含む）

大きさは、2026 年 10 月時点で、Claude の現行の主なモデルが **100 万トークン**（1 回の出力は最大 12 万 8 千トークン）、Claude Sonnet 4.5 などそれ以外のモデルは 20 万トークンです。

---

<h2 className="slide-cont">コンテキストウィンドウ（続き）</h2>

同じページは、**大きければ良いとは限らない**とも書いています。トークンが増えるにつれて精度と想起が落ちることがあり、これを **context rot** と呼んでいます。何を入れるかを選ぶことが、どれだけ入るかと同じくらい大事だ、という立場です。

<Callout type="field" title="ログを丸ごと貼る前に">

障害の調査で、数万行のログをそのまま渡したくなることがあります。ウィンドウに入ったとしても、その分だけ料金がかかり、肝心の行が埋もれます。**時刻と対象で絞ってから渡す**のが、context rot と料金の両面で理にかなっています。人に調査を頼むときと同じです。

</Callout>

会話を続けると、それまでの質問と応答はすべて次の要求の入力に積み上がっていきます（Context windows のページの説明）。長い会話ほど、1 回あたりの入力も料金も増えていきます。

## 同じ入力でも、答えがぶれる

用語集によると、**temperature** は生成の際のランダムさを決めるパラメータです。

- **高い**: 表現や答えが多様になる
- **低い**: 最も確率の高い表現と答えに寄る

ただし用語集は、**temperature を 0 にしても、出力は完全には決定的にならない**、同じ入力でも API の呼び出しごとに出力が変わることがある、と明記しています。Anthropic 自身の推論サービスでも、他社のクラウド経由でも同じだとしています。

なお、Using the Messages API のページによると、Claude 4.7 以降のモデルでは `temperature` などのサンプリングのパラメータを既定以外の値にすると 400 エラーになり、ふるまいはプロンプトで導くよう書かれています。

いずれにしても、**「同じプロンプトなら同じ答え」を前提にした作りはできません**。生成 AI を組み込んだ処理を試験するときは、出力が一字一句一致することではなく、満たすべき条件（形式・含むべき内容）で判定する必要があります。

## もっともらしい誤り — ハルシネーション

Claude のドキュメントは、最も進んだ言語モデルでも、事実と違うことや、与えた文脈と食い違うことを書くことがあり、これを**ハルシネーション**と呼ぶ、と書いています。出力を見ただけでは、正しい部分と誤った部分の見分けがつかないこともあります。

同じページが挙げる基本の対策は 3 つです。

| 対策 | 内容 |
| --- | --- |
| 「分からない」を許す | 不確かなら分からないと答えてよい、と明示する |
| 原文の引用から始めさせる | 長い文書（2 万トークン超）では、まず関係する箇所を一字一句引用させ、それに基づいて作業させる |
| 引用と出典で検証する | 主張ごとに引用と出典を付けさせ、裏付けが見つからない主張は取り下げさせる |

後の 2 つは、**答えを文書に縛りつけ、確かめられる形にする**という発想です。モデルの出力は、一次情報で確かめるまでは「下書き」として扱います。

---

## まとめ

- LLM は**次のトークンを予測する**ように事前学習され、ファインチューニングと RLHF でアシスタントに仕上げられている
- **トークン**は、扱える量・料金・速さのすべての単位。Claude では英語でおよそ 3.5 文字が 1 トークン
- **コンテキストウィンドウ**は作業用の記憶。システム・会話・ツールの結果・ツールの定義・出力のすべてが入る。大きいほど良いとは限らない（context rot）
- **temperature を 0 にしても、出力は完全には決定的にならない**。試験は一致ではなく条件で判定する
- **ハルシネーション**は最も進んだモデルでも起きる。「分からない」を許す・引用から始めさせる・出典で検証する
