## 学習済みのモデルから始める

レッスン 1〜3 では、学習の仕組みを一般的に見てきました。GPU 基盤の上で行われる学習には、モデルを一から学習するもののほかに、**すでに学習済みのモデルを読み込み、自分のデータで追加の学習をさせる**ものがあります。これを**ファインチューニング**と呼びます。

学習のループそのものは、レッスン 1 と同じです。違うのは、重みを**学習済みの値から始める**ことと、データが**用途に合わせて用意したもの**であることです。

### データの形

Hugging Face の TRL の SFT（Supervised Fine-Tuning）Trainer は、たとえば次のような形のデータを受け付けます（ドキュメントの例）。

```python
# 会話の形
{"messages": [{"role": "user", "content": "What color is the sky?"},
              {"role": "assistant", "content": "It is blue."}]}

# 問いと答えの形（prompt-completion）
{"prompt": "The sky is", "completion": " blue."}
```

利用者が用意するのは、こうした例を数多く並べたファイルです。基盤から見れば、**学習データはこの形のファイルの集まり**で、レッスン 1 の「① バッチを読む」で読まれるものです。

### loss は「次の 1 トークンを当てる」

TRL のドキュメントによると、SFT の loss は**トークン単位の交差エントロピー**で、モデルは**それまでのトークンから次のトークンを予測する**ように学習します。パディングのトークンは loss の計算から外されます。

問いと答えの形のデータでは、TRL は**既定で答えの部分のトークンだけ**で loss を計算し、問いの部分は無視します。会話の形のデータでも、`assistant_only_loss=True` にすると、アシスタントの応答だけで loss を計算します。

つまりファインチューニングは、「この問いには、こう答える」という例を見せて、**答えの部分を出せるように重みを少し動かす**作業です。

学習中のログには、TRL のドキュメントが挙げるように、累計のステップ数（`global_step`）、エポック、処理したトークン数（`num_tokens`）、loss などが記録されます。利用者が「loss が下がらない」と言うのは、このログを見ています。

---

## フルファインチューニング: 全部の重みを動かす

最も素直な方法は、**すべての重みを学習の対象にする**ことです。これを**フルファインチューニング**と呼びます。

この場合、レッスン 1 で見たメモリの内訳がそのまま当てはまります。すべての重みに勾配とオプティマイザの状態が付くので、重みだけを載せる推論とは桁が違うメモリが要ります。

QLoRA の論文は、LLaMA 65B を通常の 16 ビットでファインチューニングすると、**780 GB を超える GPU メモリ**が要ると書いています。80 GB の GPU なら 10 枚以上で、レッスン 2 の FSDP のような分割が前提になります。

チェックポイントも、レッスン 3 の再開用のものがそのまま必要です。

---

## LoRA: 小さな行列だけを学習する

**LoRA**（Low-Rank Adaptation）は、**元の重みを凍結して動かさず**、各層に小さな行列を足して、そこだけを学習する方法です（Hu et al., 2021）。

<Figure name="lora-adapter" caption="元の重み W は凍結し、横に足した小さな行列 A と B だけを学習する" source="Hu et al., LoRA（2021）を元に作図" />

凍結した重みには勾配もオプティマイザの状態も要らないので、メモリが大きく減ります。LoRA の論文は、GPT-3 175B を Adam でファインチューニングする場合と比べて、次のように報告しています。

| | フルファインチューニング | LoRA |
| --- | --- | --- |
| 学習するパラメータの数 | 全部 | **約 1 万分の 1**（論文の要旨の比較） |
| 学習中の VRAM | 1.2 TB | **350 GB** |
| 保存するチェックポイント | 350 GB | **35 MB**（r = 4、一部の行列だけに適用した場合） |

論文は、これによって**ずっと少ない GPU で学習でき、I/O のボトルネックも避けられる**としています。

### 推論ではどうなるか

学習が終わると、LoRA で学習した行列（`A` と `B`）は、元の重みに**足し込む（マージする）**ことができます。論文によると、マージすれば推論のときに**余計な遅延は増えません**。

もう 1 つの使い方は、マージせずに `A` と `B` だけを別に持ち、**用途ごとに差し替える**ことです。論文は、LoRA の重みだけを入れ替えれば、配備したまま安く別のタスクに切り替えられるとしています。PEFT の README も、多くの場合**チェックポイントは数 MB** で済むと書いています。

<Callout type="pitfall" title="35 MB のファイルだけでは推論できない">

LoRA の論文自身が注記しているとおり、配備するときには**元のモデル（GPT-3 なら 350 GB）が別に必要**です。小さいのは「差分」だけで、元の重みは消えていません。

利用者から「ファインチューニングしたモデルは数十 MB です」と聞いたら、**推論のサーバーには元のモデルも置く**必要があるかを確かめます。ストレージの見積もりでは、元のモデル 1 つと、用途ごとの小さなアダプタが複数、という形になります。

</Callout>

---

## QLoRA: 元の重みを 4 ビットにする

LoRA でも、凍結した元の重みは GPU のメモリに載せる必要があります。**QLoRA** は、この元の重みを **4 ビットに量子化**したうえで、LoRA の行列を学習します（Dettmers et al., 2023）。勾配は、凍結した 4 ビットのモデルを通って LoRA の行列に流れます。

論文は、メモリを減らすために次の 3 つを導入したとしています。

- **4-bit NormalFloat（NF4）**: 正規分布に近い重みに合わせた 4 ビットのデータ型
- **Double Quantization**: 量子化のための定数まで量子化して、平均のメモリをさらに減らす
- **Paged Optimizers**: メモリの使用量が一時的に跳ね上がるのを吸収する

その結果、**65B のモデルを 48 GB の GPU 1 枚でファインチューニングできた**、と報告しています。16 ビットのフルファインチューニングで 780 GB を超えていたものが、48 GB 未満に下がったという比較です。

---

## 基盤から見た違い

同じ「ファインチューニング」でも、方法によって基盤への要求が大きく変わります。数字はそれぞれの論文の条件での値です。

| | フル | LoRA | QLoRA |
| --- | --- | --- | --- |
| 学習する重み | 全部 | 足した小さな行列だけ | 足した小さな行列だけ |
| 元の重み | 学習する | 凍結 | 凍結し、4 ビットで持つ |
| GPU の要求の例 | LLaMA 65B で 780 GB 超（QLoRA の論文） | GPT-3 175B で 1.2 TB → 350 GB（LoRA の論文） | LLaMA 65B を 48 GB の GPU 1 枚（QLoRA の論文） |
| 成果物 | モデル全体 | 小さなアダプタ（＋元のモデル） | 小さなアダプタ（＋元のモデル） |

利用者から「ファインチューニングに GPU が何枚要るか」と聞かれたら、まず**フルか LoRA 系か**を確かめます。それによって、必要な GPU が桁で変わるからです。

---

## まとめ

- ファインチューニングは、**学習済みのモデルを読み込み、用途に合わせたデータで追加の学習をする**こと。ループはレッスン 1 と同じ
- SFT のデータは「会話」や「問いと答え」の形。loss は次のトークンを当てる交差エントロピーで、**既定では答えの部分だけ**で計算する（TRL）
- **フルファインチューニング**はすべての重みを学習するので、レッスン 1 のメモリの内訳がそのまま当てはまる
- **LoRA** は元の重みを凍結し、小さな行列だけを学習する。GPT-3 175B で学習中の VRAM が 1.2 TB → 350 GB、チェックポイントが 350 GB → 35 MB
- LoRA の成果物は差分だけ。**推論には元のモデルが別に要る**。マージすれば推論の遅延は増えない
- **QLoRA** は元の重みを 4 ビットにして、65B のモデルを 48 GB の GPU 1 枚で学習できた
