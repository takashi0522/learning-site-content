## KVM — カーネルの機能としての仮想化

Linux の仮想化の中心は **KVM**（Kernel-based Virtual Machine）です。カーネルのドキュメントによると、KVM の API は、**ファイルディスクリプタと、それに対する ioctl** でできています。

1. `/dev/kvm` を開くと、KVM のサブシステムへのハンドルが得られる
2. そのハンドルに `KVM_CREATE_VM` を発行すると、**VM のファイルディスクリプタ**ができる
3. VM のディスクリプタに `KVM_CREATE_VCPU` を発行すると、**仮想 CPU のディスクリプタ**ができる

VM に対する操作（メモリの配置など）は、VM を作った**同じプロセス**から発行しなければなりません。ドキュメントは、VM とその資源は、作ったプロセスではなく**ファイルディスクリプタに結びついていて**、最後の参照が閉じられるまで解放されない、と書いています。

つまり KVM は、**ユーザー空間のプロセスが、ファイルディスクリプタと ioctl でカーネルに VM を作らせて動かす**仕組みです（ホストからは、VM を動かしているプロセスとして見える、というのがこのコースの整理）。Linux コース レッスン 1 の「ユーザー空間とカーネル空間」の境界が、ここにも出てきます。

## デバイスをどう渡すか

仮想マシンの中のゲストがデバイスを使うには、2 つの道があります。

<Figure name="device-assignment" caption="ホストが模した仮想デバイスか、IOMMU で守った直接の割り当てか。SR-IOV は 1 枚を複数に見せる" source="Linux Kernel Documentation の VFIO と PCI Express I/O Virtualization Howto を元に作図" />

VFIO のドキュメントは、**直接の割り当て（device assignment）**について、仮想マシンは**最高の I/O 性能**が要るときにデバイスを直接使うことが多い、と書いています。デバイスとホストから見れば、VM は単なる**ユーザー空間のドライバ**になり、**レイテンシが大きく下がり、帯域が上がり、ベアメタル用のドライバをそのまま使える**、という利点があります（ドキュメントは数値を示していません）。ドキュメントは、高性能計算でのネットワークアダプタや計算用のアクセラレータを、直接の利用が効く例に挙げています。

一方で、直接割り当てたデバイスは、その VM が使うものになります（このコースの整理）。複数の VM で 1 枚を分けるには、別の仕組み（このレッスンの SR-IOV や、レッスン 6 の vGPU・MIG）が要ります。

---

## IOMMU — デバイスに勝手にメモリを触らせない

VFIO のドキュメントは、デバイスの機能のうち、安全を保つうえで最も重要なのは **DMA**（デバイスがメモリを直接読み書きする仕組み）だと書いています。デバイスにシステムのメモリを読み書きさせるのは、システム全体の完全性にとって最大の危険だからです。

そこで使うのが **IOMMU** です（x86 では Intel VT-d や AMD-Vi）。ドキュメントによると、IOMMU によって、デバイスを**ほかのデバイスや任意のメモリへのアクセスから隔離**でき、仮想マシンへの安全な直接割り当てができるようになります。ハードウェアコース レッスン 5 の PCIe の上に、この隔離の層が乗っています。

---

## 割り当ての単位は IOMMU グループ

ただし、隔離は**いつもデバイス 1 つ単位でできるとは限りません**。ドキュメントは、マルチファンクションのデバイスの機能どうしに裏口がある場合や、ACS（Access Control Services）に対応しないブリッジがあると、IOMMU を通らずに通信が回り込みうる、と書いています。そこで IOMMU の API は、**ほかのすべてのデバイスから隔離できるデバイスの集まり**を **IOMMU グループ**として扱い、VFIO はこのグループを**所有の単位**にします。

ドキュメントの例で、デバイスのグループを確かめます。

```bash
$ readlink /sys/bus/pci/devices/0000:06:0d.0/iommu_group
../../../../kernel/iommu_groups/26
$ ls -l /sys/bus/pci/devices/0000:06:0d.0/iommu_group/devices
... 0000:00:1e.0 -> ../../../../devices/pci0000:00/0000:00:1e.0
... 0000:06:0d.0 -> ../../../../devices/pci0000:00/0000:00:1e.0/0000:06:0d.0
... 0000:06:0d.1 -> ../../../../devices/pci0000:00/0000:00:1e.0/0000:06:0d.1
```

---

<h2 className="slide-cont">割り当ての単位は IOMMU グループ（続き）</h2>

ドキュメントの例（機種は示されていない）では、このデバイス（`06:0d.0`）は IOMMU グループ 26 に属し、同じグループに `06:0d.1` と、ブリッジの `00:1e.0` がいます。ドキュメントによると、このデバイスは PCIe から PCI へのブリッジの後ろにあるため、**`06:0d.1` も同じ手順で vfio-pci に結びつける必要があります**（ホストのドライバを持たないブリッジは除く）。グループの中に複数のデバイスがあると、**そのすべてを VFIO のドライバに結びつけるまで、グループは使えません**。

<Callout type="field" title="パススルーを前提にサーバーを選ぶなら">

渡したいデバイス（GPU や NIC）が、ほかのデバイスと同じ IOMMU グループに入っていると、そのデバイスもホストのドライバから外し、VFIO の側に寄せる必要があります（ホストのドライバを持たないブリッジは除く）。どのデバイスがどのグループに入るかは、サーバーの PCIe のつながり方とブリッジの性質で決まるので、**導入前に実機で `iommu_groups` を確かめる**価値があります（このコースの整理）。

</Callout>

## SR-IOV — 1 枚のデバイスを複数に見せる

直接の割り当てはデバイスを 1 つの VM が専有します。**SR-IOV**（ハードウェアコース レッスン 5 でも触れた）（Single Root I/O Virtualization）は、カーネルのドキュメントによると、**1 つの物理デバイスを複数の仮想デバイスに見せる** PCI Express の拡張機能です。

| 名前 | 中身 |
| --- | --- |
| **PF**（Physical Function） | 物理デバイスそのもの。VF の割り当てを制御する |
| **VF**（Virtual Function） | 仮想のデバイス。それぞれが独自の PCI の構成空間とメモリ空間を持ち、**本物の PCI デバイスのように**見える |

ドキュメントによると、SR-IOV は既定では無効で、有効にするまで PF はふつうの PCIe デバイスとして振る舞います。有効にする方法は 2 つあり、新しいデバイスには 2 つ目が推奨されています。

- PF のドライバが有効にする（モジュールのパラメータで VF の数を決めるものもある）
- sysfs の `sriov_numvfs` に、作りたい VF の数を書き込む

```bash
echo 4 > /sys/bus/pci/devices/<DOMAIN:BUS:DEVICE.FUNCTION>/sriov_numvfs
```

VF はカーネルからは**ホットプラグされた PCI デバイス**として扱われ、普通の PCI デバイスと同じようにドライバで動きます。この VF を VFIO で VM に直接割り当てれば、1 枚の NIC を複数の VM で分けて、それぞれに直接割り当てる構成が作れます（このコースの整理）。Kubernetes で RDMA の NIC を Pod に渡す方法のうち SR-IOV を使うもの（AI 基盤コース レッスン 5）は、この VF を Pod に専有させています。

---

## まとめ

- **KVM** は `/dev/kvm` への ioctl で VM と仮想 CPU を作る。ホストから見れば、VM は KVM を使う**ユーザー空間のプロセス**
- デバイスの**直接割り当て**は、レイテンシが小さく帯域が大きく、ベアメタルのドライバを使える。その代わりデバイスは VM が専有する
- 直接割り当てには **IOMMU** が要る。DMA でメモリを勝手に触らせないための隔離
- 割り当ての単位は **IOMMU グループ**。同じグループのデバイスは、ホストのドライバを持たないブリッジを除いて VFIO に結びつけないと使えない。`/sys/.../iommu_group` で確かめる
- **SR-IOV** は 1 つの PF を複数の **VF** に見せる。`sriov_numvfs` で作り、VF を VM に直接割り当てる
