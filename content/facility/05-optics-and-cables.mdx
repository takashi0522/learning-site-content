## フォームファクタ: 形と速度の対応

トランシーバの形状（フォームファクタ）は、**収容できるレーン数**で決まります。レッスン 4 で見た「速度 = レーン数 × レーン速度」がそのまま形に反映されています。

| 形状 | レーン数 | 代表的な速度 | 備考 |
| --- | --- | --- | --- |
| **SFP+** | 1 | 10G | |
| **SFP28** | 1 | **25G** | SFP+ と同じ形状 |
| SFP56 | 1 | 50G | |
| **QSFP+** | **4** | 40G (4×10G) | Q = Quad（4 レーン） |
| **QSFP28** | **4** | **100G (4×25G)** | |
| QSFP56 | 4 | 200G (4×50G) | |
| **QSFP-DD** | **8** | **400G / 800G** | DD = Double Density |
| **OSFP** | **8** | **400G / 800G** | QSFP-DD より大きく放熱に有利 |

---

<h2 className="slide-cont">フォームファクタ: 形と速度の対応（続き）</h2>

<Callout type="tip" title="物理的な互換性の原則">

**レーン数が同じか少ないモジュールは、多くの場合そのまま挿さります。**

```text
QSFP28 のポート ← QSFP+ (40G) を挿す     → 動くことが多い
QSFP-DD のポート ← QSFP28 (100G) を挿す  → 動くことが多い（DD は後方互換を意図した設計）
SFP28 のポート  ← SFP+ (10G) を挿す      → 動くことが多い

QSFP28 のポート ← SFP28 を挿す           → 形が違うので物理的に不可
                                            （QSFP-to-SFP アダプタを使えば可能）
```

ただし**対応は機器のファームウェア次第**です。物理的に挿さることと、その機器がサポートしていることは別問題なので、必ずベンダーの対応表を確認してください。

QSFP-DD と OSFP は**互いに互換性がありません**。ポートがどちらかを確認して発注する必要があります。

</Callout>

## DAC / AOC / 光モジュール

同じ 2 点間を繋ぐのに、3 つの選択肢があります。**距離とコストで決まります。**

| | **DAC** | **AOC** | **光モジュール + ファイバ** |
| --- | --- | --- | --- |
| 実体 | 銅線ケーブルの両端にコネクタ直付け | 光ケーブルの両端にトランシーバ直付け | トランシーバとファイバが別 |
| 距離 | **IEEE の目標で 2〜5m 以上**（レーン速度が上がるほど短い。下の表） | DAC より長い（製品による） | **規格による**（100G でも SMF で 40km 以上を目標にした規格がある） |
| 価格 | **最も安い** | 中間 | **最も高い** |
| 消費電力 | **ほぼゼロ**（パッシブ） | 小さい | 中 |
| 交換性 | ケーブルごと交換 | ケーブルごと交換 | **モジュールだけ交換できる** |
| 主な用途 | **ラック内（サーバー〜ToR）** | ラック間・短距離 | **ラック間・フロア間・長距離** |

### DAC の距離制限

DAC は銅線なので、**レーンあたりの信号速度が上がるほど到達距離が短くなります**。効くのはポートの合計速度ではなく、**1 レーンの速度**です（レッスン 4）。IEEE 802.3 の各規格が掲げた銅線の到達距離の目標は次のとおりです。

```text
25G / レーン  (SFP28、QSFP28 の 4×25G)      : 5m 以上  （802.3by / 802.3bj）
50G / レーン  (SFP56、QSFP56 の 4×50G)      : 3m 以上  （802.3cd）
100G / レーン (SFP112、QSFP112、OSFP など)  : 2m 以上  （802.3ck）
```

同じ「100G」でも、4×25G の QSFP28 なら目標は 5m、1×100G の SFP112 なら 2m です。これらは規格化の目標（少なくともこの距離）なので、実際の上限は製品のデータシートで確認します。

さらに速い世代で銅線がどこまで短くなるか、銅線と光の間を埋める選択肢（AEC・LPO・CPO）はレッスン 8 で扱います。

---

<h2 className="slide-cont">DAC / AOC / 光モジュール（続き）</h2>

<Callout type="pitfall">

**「DAC は 5m まで」と一律に覚えていると、高速化した際に失敗します。**

25G/レーンで 5m の DAC を使っていた構成を 100G/レーンの世代（SFP112 など）に上げると、目標は 2m まで下がり、届かないことがあります。ラック内であっても、上下に離れた機器間では 2m を超えることがあります。

距離が足りない場合の選択肢です。

- **ACC（Active Copper Cable）** … 信号を増幅する回路を内蔵した銅ケーブル。DAC より長く届く製品がある（距離は製品と速度による）
- **AOC** … 光ケーブル。DAC より長い距離をつなげる（距離は製品による）

発注前に、**ラック図上で実際のケーブル経路長を測ってください。** 直線距離ではなく、ケーブルマネージャを通す実際の取り回しの長さです。余裕を見すぎると余長が排気を塞ぎ（レッスン 3）、足りないと届きません。

</Callout>

### AOC と光モジュールの使い分け

AOC は「光モジュール 2 個 + ファイバ」を一体化したもので、両端が固定されています。

| | AOC が有利 | モジュール + ファイバが有利 |
| --- | --- | --- |
| コスト | 短〜中距離では安い | 長距離では逆転 |
| 配線 | **清掃不要・極性を気にしなくてよい** | パッチパネル経由の構造化配線ができる |
| 障害時 | ケーブルごと交換（両端の作業が必要） | **片端のモジュール交換で済む** |
| 柔軟性 | 長さが固定 | 経路変更に対応しやすい |

---

<h2 className="slide-cont">DAC / AOC / 光モジュール（続き）</h2>

<Callout type="field">

**AOC は「configure して終わり」の構成に向きます。** コネクタ端面の清掃が不要で、MPO の極性（レッスン 3）も考えなくてよいため、施工ミスが起きにくいのが実務上の利点です。

一方、**パッチパネルを使った構造化配線には使えません**（両端が固定されているため）。ラック間を跨ぐ本設の配線には、モジュール + ファイバの構成を選びます。

- ラック内、隣接ラック間の直結 → DAC / AOC
- パッチパネル経由、フロアを跨ぐ → **モジュール + ファイバ**

</Callout>

## ファイバの種類

モジュールを選んだら、対応するファイバが必要です。

| 種別 | 通称 | 被覆色 | 用途 |
| --- | --- | --- | --- |
| **OM3** | マルチモード | **水色** | `SR` 系 |
| **OM4** | マルチモード | 水色 / 紫 | `SR` 系 |
| **OS2** | シングルモード | **黄色** | `DR` / `FR` / `LR` / `ER`、長距離 |

```text
100GBASE-SR4 などの 100G のマルチモード規格
  規格化の目標: MMF で 100m 以上（802.3bm）
  OM3 / OM4 それぞれでの到達距離 → モジュールのデータシートで確認する
```

<Callout type="warning" title="MMF と SMF は互換性がない">

**マルチモード用のモジュール（SR）にシングルモードファイバを挿しても、逆も、動きません。** コネクタ形状（LC）は同じなので物理的には挿さり、これが混乱の元になります。

「水色のケーブルと黄色のケーブルは別物」と覚えておくだけでも、現場での取り違えをかなり防げます。

なお、既設のファイバがどちらか分からない場合は、被覆の印字を確認してください。`OM4` や `OS2` といった表記がケーブル本体に印刷されています。

</Callout>

### コネクタ形状

---

<h2 className="slide-cont">ファイバの種類（続き）</h2>

| コネクタ | 芯数 | 使われる規格 |
| --- | --- | --- |
| **LC**（2 芯 1 組） | 2 | `LR4`、`FR4`、`100GBASE-DR`（1 レーン）、10G/25G の `SR`/`LR` |
| **MPO-12** | 12（うち 8 使用） | **`100GBASE-SR4`**、`400GBASE-DR4` |
| MPO-16 | 16 | `400GBASE-SR8` |

表は代表例です。実際のコネクタはモジュールのデータシートで確認してください。多くの場合、レッスン 4 で見た「レーン数」がコネクタの選択に繋がっています。

- **波長多重するもの（`LR4` など）** → 1 組の芯に集約できるので **LC**
- **1 レーンのもの（`100GBASE-DR` など）** → これも **LC**
- **物理的に並列伝送するもの（`SR4`、`DR4` など）** → レーン数分の芯が必要なので **MPO**

## サードパーティ製モジュール

純正品は高価なため、互換品（FS.com、ProLabs など）を使うことが広く行われています。

```bash
# モジュールのベンダー情報は EEPROM から読める
sudo ethtool -m eth0 | grep -iE 'vendor|part|serial'
```

<Callout type="pitfall" title="ベンダーロックへの対処">

一部のネットワーク機器は、**純正以外のトランシーバを対応外として扱い、そのポートを使えなくする**ことがあります。

たとえば Cisco の Catalyst 3850 のトラブルシューティング文書は、サードパーティの SFP を動かすための設定として `service unsupported-transceiver` と `no errdisable detect cause gbic-invalid` を挙げ、対応状況は Cisco Optics Interoperability Matrix で確認するよう勧めています。

互換品を使う場合は、**接続先の機器で動作するかを販売元に確認してから発注**します。

```text
発注時に伝える情報:
  ・接続する機器のメーカーと型番
  ・速度と規格（100GBASE-SR4 など）
  ・必要な距離
```

検査を緩める設定を使ったときに機器ベンダーのサポートがどう扱うかは、ベンダーの規定によります。本番環境では事前に確認してください。

</Callout>

<Callout type="note">

互換品を使うときは、次の点に留意してください。

- **障害時の切り分けで疑われる**。純正・互換を混在させず、記録を残しておく
- 機器ベンダーのサポートが「まず純正に交換してください」と言ってくる可能性がある
- **予備を持っておく**。互換品は納期が読みにくいことがある

</Callout>

## 運用: 何が挿さっているかを把握する

```bash
# 全インターフェースのモジュール情報を一覧する
for i in $(ls /sys/class/net | grep -v lo); do
  info=$(sudo ethtool -m "$i" 2>/dev/null) || continue
  printf "%-10s %-24s %-28s %s\n" "$i" \
    "$(echo "$info" | awk -F': *' '/Vendor name/{print $2}')" \
    "$(echo "$info" | awk -F': *' '/Vendor PN/{print $2}')" \
    "$(echo "$info" | sed -n 's/^[[:space:]]*Transceiver type[[:space:]]*: //p' | head -1)"
done
```

```text
# 出力の例（項目の中身は NIC・ドライバ・モジュールによって変わる）
eth0       FS                       QSFP28-SR4-100G              100G Ethernet: 100G Base-SR4 or 25GBase-SR
eno1       Intel Corp.              SFP-10G-SR                   10G Ethernet: 10G Base-SR
```

`Vendor name`、`Vendor PN`、`Transceiver type` は、ethtool がモジュールの EEPROM を解読して表示する項目名です（ethtool のソース）。`Transceiver type` は複数行出ることがあるので、ここでは最初の 1 行だけを取っています。

<Callout type="field">

**この一覧を定期的に取得して保存しておくと、構成管理の手間が大きく減ります。**

- 機器更改時に「何を何個発注するか」が即座に分かる
- 障害時に「同じ型番の予備があるか」を現地に行かずに判断できる
- レッスン 4 で触れた受信光レベルの推移と併せて記録すれば、劣化の検知にも使える

```bash
# 光レベルも含めて記録する
# 受信光の項目名は SFP 系が Receiver signal、QSFP 系が Rcvr signal
sudo ethtool -m eth0 | grep -E 'Receiver signal|Rcvr signal|Laser output|Module temperature'
```

構成管理ツールを入れていなくても、cron でこの出力をファイルに残すだけで実用的な台帳になります。

</Callout>

## まとめ

- フォームファクタは**収容レーン数**で決まる。SFP 系 = 1 レーン、QSFP 系 = 4、QSFP-DD / OSFP = 8
- **QSFP-DD と OSFP は互換性がない**。ポート側を確認して発注する
- **DAC はレーンあたりの速度が上がるほど短くなる**。IEEE の目標は 25G/レーンで 5m、50G/レーンで 3m、100G/レーンで 2m
- 距離が足りないときは ACC → AOC → モジュール + ファイバ の順で検討
- **AOC は清掃も極性も不要**で施工ミスが起きにくいが、パッチパネル経由には使えない
- MMF（水色・`SR`）と SMF（黄色・`LR`/`DR`）は**コネクタが同じでも互換性がない**
- 多くの場合、並列伝送（`SR4` など）は MPO、波長多重（`LR4` など）や 1 レーンのものは LC。**レーン構成がコネクタに効く**
- 機器によっては純正以外のトランシーバを対応外として扱う。互換品は**接続先の機器での動作を確認してから**使う
- `ethtool -m` の一覧を定期取得すれば、実用的な構成台帳になる
