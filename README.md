# infra学習ノート

インフラ基盤（OS・運用・ハードウェア・GPU・ネットワーク・ファシリティ・AI 基盤・GPU 基盤の導入・ミドルウェア・認証）を、手順の暗記ではなく仕組みから理解するための個人用ラーニングサイト。

同じ教材を **記事モード** と **スライドモード** の両方で読め、確認クイズと進捗トラッキングが付いています。

## Web で読む

https://takashi0522.github.io/learning-site-content/

`main` に push すると GitHub Actions がビルドして、GitHub Pages に出し直します（`.github/workflows/pages.yml`）。

## 手元で動かす

[Node.js](https://nodejs.org/) 18.18 以上が必要です（24 で動作を確認しています）。

GitHub から取得する場合は、リポジトリの「Code」→「Download ZIP」で落として展開するか、`git clone` します。

```bash
git clone https://github.com/takashi0522/learning-site-content.git
cd learning-site-content
```

展開したフォルダで次を実行します。初回の `npm install` は依存パッケージを取得するので数分かかります。

```bash
npm install
npm run dev
```

ブラウザで http://localhost:3000 を開きます。止めるときはターミナルで Ctrl+C を押します。

3000 番が使えない環境では、ポートを指定して起動します（例: `npm run dev -- --port 4321` なら http://localhost:4321）。

進捗とクイズの回答はブラウザの localStorage に保存されます。別の PC や別のブラウザには引き継がれません。

```bash
npm run build      # out/ に静的サイトを生成
npm run start      # 生成物をローカルで確認
```

## ラボ

`/labs` は、読むのではなく**自分で判断して確かめる**ための演習です。
形式は 3 つあります。

- **1 手ずつ選ぶ形式** — 「次に何が起きるか」を選び、選んでから仕組みの説明が出ます
- **組み立てる形式** — 自分で構成を作り、制約を満たせたかを検証します
- **置き場所を選ぶ形式** — 配置を変えると所要時間が数字で変わります

どちらも採点はしません。間違えても正解は出ず、考え直すための手がかりだけが出ます。

| ラボ | 内容 |
| --- | --- |
| パケットはどこを通るのか | 別サブネット宛のパケットを 1 ホップずつ追う。L2 と L3 の宛先が食い違うこと、IP ヘッダが変わらないことを確かめる |
| ラックを設計する | 42U のラックに機器を積む。お題は「何台積めるのか」「空いた U を塞ぐ」「電源をどう配るか」の 3 つ |
| GPU ラックに電源を引く | 1 台 10kW の機械を三相給電でどう収めるか。冗長を取るか台数を取るかを決める |
| 重さと配線で詰まる | フロア荷重・重心・パッチコードの届く範囲。U も電気も足りているのに載らない場面 |
| ファブリックのどこを通るのか | スパインが 2 台あるとき何が経路を選ぶか。ECMP とオーバーサブスクリプション |
| GPU クラスタのネットワーク | なぜ 4 系統に分けるのか。計算ファブリックのノンブロッキングとレール最適化 |
| GPU ジョブを配置する | 同じ 8 GPU でも、1 ノードに収まるか跨ぐかで 19ms と 350ms に分かれる |
| PyTorch で学習を回す | 公式チュートリアルの学習コードを 1 行ずつ追う。各行が CPU・GPU・ストレージのどこで動くか、再開に何を保存するか |

### 使えるコンポーネント

```mdx
<Callout type="field">

補足ボックス。type は note / tip / warning / pitfall / field。
field は「実務でどう効くか」を書く枠です。

</Callout>

<Quiz
  id="q1"
  question="設問文"
  options={["選択肢1", "選択肢2", "選択肢3"]}
  answer={1}
  explanation="正解したときに表示される解説"
/>
```

> `Quiz` の `id` は解答結果の保存キーになります。公開後に変更すると過去の解答が失われるので、一度決めたら変えないでください。

```mdx
<Figure name="lvm-stack" caption="図の説明" />
```

> 図は `src/components/figures/` にインライン SVG として持っていて、`name` はその ID です。
> テーマ (ライト/ダーク) とコース別のアクセント色に自動で追従します。
> 新しい図は `src/components/figures/<course>.tsx` に書き、`registry.ts` に ID を登録すると MDX から呼べます。

**図はクリックすると拡大表示されます。** ベクタなので何倍にしても潰れません。
拡大中は `＋` `−` でさらに 3 倍まで、`0` で等倍、`Esc` で閉じます。
スライドモードで縮小されている図も、拡大すれば画面いっぱいの大きさで読めます。

### コースを増やす

`content/<コース>/course.json` を作ります。

```json
{
  "title": "コース名",
  "subtitle": "ヘッダーに出る英字ラベル",
  "description": "カードに出る説明",
  "order": 5,
  "accent": "linux",
  "level": "基礎",
  "status": "ready"
}
```

`accent` は `linux` / `ops` / `hardware` / `gpu` / `network` / `facility` / `ai` / `gpunet` / `buildout` / `middleware` / `auth` のいずれか（色のテーマ）。新しい色を足す場合は `src/app/globals.css` の `[data-accent="..."]` に定義を追加し、`src/lib/content.ts` の `Course` 型を広げます。

`status` が `draft` のコースには一覧で「準備中」バッジが付きます。

## 公開するとき

`npm run build` が生成する `out/` ディレクトリが完成品です。

- **Cloudflare Pages / Vercel** — ビルドコマンド `npm run build`、出力ディレクトリ `out`
- **GitHub Pages** — `.github/workflows/pages.yml` がビルドして出す。リポジトリ名のサブパスに置かれるので、環境変数 `NEXT_PUBLIC_BASE_PATH=/<リポジトリ名>` でビルドする（ワークフローが設定済み）

進捗データはブラウザにしか保存されないため、公開しても閲覧者同士や運営者に学習履歴が共有されることはありません。

## 収録済みの教材

全 75 レッスン・12 コース。「なぜそう動くか」を扱うコースと、「実際に何を打つか」を扱う運用コース、そして「何を順番に決めるか」を扱う導入コースを分けています。

### 1. Linux / OS 基礎（6 レッスン）

カーネルとユーザー空間の境界から始めて、最後にコンテナとしてすべてが繋がる構成。

1. カーネル空間とユーザー空間 — 特権レベル、システムコール、vDSO
2. プロセスとスケジューラ — D 状態、EEVDF、ロードアベレージの正体、PSI
3. 仮想メモリとページキャッシュ — demand paging、available、OOM Killer、THP
4. ファイルシステムと VFS — inode と dentry、削除しても空かない理由、fsync
5. systemd によるサービス管理 — Requires と After、Type、drop-in
6. namespace と cgroup — コンテナの中身

### 2. 運用オペレーション（6 レッスン）

日々サーバーに入って実際に打つコマンドと手順。上のコースが「仕組み」なら、こちらは「手順」。

1. 障害対応の初動 — vmstat の読み方、証拠保全、steal time
2. ログを読む・残す — journalctl の絞り込み、永続化、logrotate の postrotate
3. ユーザー・権限・SSH — sudoers の落とし穴、鍵のパーミッション、締め出し回避
4. ストレージ運用と容量逼迫 — LVM オンライン拡張、fstab、truncate と rm の違い
5. パッケージ管理と更新戦略 — 更新前の確認、バージョン固定、再起動の要否判断
6. 設定変更を安全に・確実に残す — 一時と恒久、ネットワーク変更の戻し手段

### 3. サーバーハードウェア（6 レッスン）

OS から見える数字が「なぜその値になるか」を物理層から説明できるようにする。

1. メモリ階層とレイテンシの桁感覚 — キャッシュライン、False Sharing、NUMA
2. CPU の構造と周波数の実際 — SMT、ターボの上限、C-state、脆弱性緩和
3. メモリサブシステムと ECC — チャネルと帯域、CE を予兆として扱う
4. ストレージの内部構造と RAID — NAND の制約、書き込みペナルティ、PLP
5. PCIe と割り込み — 帯域計算、リンクの downgrade、IRQ の偏り
6. 電源・冷却と BMC — SEL、給電系統、サーマルスロットリング

### 4. GPU / アクセラレータ（6 レッスン）

CPU サーバーとは前提が違う部分を切り出したコース。

1. NVIDIA GPU の構造とドライバスタック — HBM、NVLink、CUDA のバージョン互換
2. GPU サーバーの運用 — Xid エラー、永続モード、コンテナ、DCGM
3. マルチ GPU と GPU 間通信 — NCCL、集合通信、InfiniBand / RoCE、GPUDirect
4. GPU の性能を測る・共有する — SM_ACTIVE、プロファイリング、MIG / MPS
5. 推論サービングの最適化 — KV キャッシュ、連続バッチング、量子化、TTFT
6. CUDA の実行モデルと向き不向き — warp、コアレッシング、演算強度、転送コスト

### 5. ネットワーク（6 レッスン）

パケットの経路を追い、どの層で落ちているかをカウンタから特定できるようにする。

1. パケットが NIC からアプリに届くまで — NAPI、層ごとのドロップ、BDP
2. L2 スイッチングと VLAN・ボンディング — MTU 不一致、LACP の単一フロー制約
3. IP とルーティングの実際 — 非対称経路、rp_filter、PMTU ブラックホール
4. TCP の状態遷移とチューニング — CLOSE_WAIT と TIME_WAIT の違い、輻輳制御
5. 名前解決の経路と DNS の落とし穴 — NSS、ndots、アプリ側キャッシュ
6. TLS・HTTP とロードバランサ — 中間証明書、HTTP/2 の HOL、X-Forwarded-For

### 6. データセンター・ファシリティ（8 レッスン）

ラックに機器を載せる前に決まっていること。物理層の判断材料。

1. ラックと電源容量 — ブレーカーの 80% ルール、A/B 冗長は各系統 50% 以下
2. 冷却とエアフロー — 吸気温度、ブランクパネル、空冷の限界と液冷
3. 構造化配線とラック内配線 — ToR / EoR、パッチパネル、LLDP、MPO 極性
4. イーサネットの速度規格とレーン — 100GBASE-SR4 の読み方、PAM4、FEC 不一致
5. 光モジュールと DAC / AOC の選び方 — QSFP 系の対応、距離制限、互換品
6. ブレイクアウトと配線設計 — 400G→4×100G の成立条件、オーバーサブスクリプション
7. 液冷の仕組み — HGX サーバーを例に、CDU・二次側ループ・ASHRAE の水質と温度区分
8. 光インターコネクトと電力 — 銅線の届く距離、DSP・LPO・CPO、800G 世代の消費電力

### 7. AI 基盤（7 レッスン）

GPU を並べただけでは学習は速くなりません。GPU を実際に使い切るための層。

1. AI 基盤の全体像 — 学習と推論の要求の違い、VRAM 見積もり、ボトルネックの地図
2. InfiniBand とロスレスファブリック — Subnet Manager、ibdiagnet、RoCE との比較、SHARP
3. NCCL の動作とチューニング — Ring / Tree、nccl-tests での実測、経路の切り分け
4. AI ワークロードのストレージ — 小さいファイル問題、シャード化、チェックポイント、GDS
5. Kubernetes での GPU 運用 — device plugin、GPU Operator、/dev/shm、RDMA、Topology Manager
6. 分散学習ジョブのスケジューリング — gang scheduling、Slurm との比較、障害時の自動復旧
7. AI 基盤のストレージ構成 — NFS と並列ファイルシステム、Lustre のストライプ、ストレージ用ファブリック

### 8. GPU ネットワーク（6 レッスン）

GPU 間の計算ファブリックを Ethernet で組むためのコース。InfiniBand との比較ではなく、RoCE で成立させる側から書いている。

1. AI のトラフィックはなぜ特別なのか — 少数・巨大・同期、バースト、go-back-N、最悪のリンクが全体を決める
2. ロスレスを作る — PFC — 802.1Qbb、優先度クラス、headroom とケーブル長、巻き添え、デッドロック
3. 輻輳を手前で消す — ECN と DCQCN — CP / NP / RP、CNP、閾値の順序、DSCP 26 と 48
4. 経路が偏る — ECMP と適応ルーティング — ハッシュ衝突、エントロピー、フローレット、パケットスプレー
5. 各社が足しているもの — Spectrum-X、Arista Etherlink、Cisco Silicon One、Ultra Ethernet
6. RoCE ファブリックを設計する — QoS の一式、MTU、揃える範囲、IB との選択

### 9. GPU 基盤の導入（6 レッスン）

NVIDIA のリファレンスアーキテクチャを読み解き、設計から運用引き渡しまでを順に辿る。他コースが部品の仕組みなら、こちらは「何を順番に決めて、どう確かめるか」。

1. リファレンスアーキテクチャを読む — BasePOD / SuperPOD / NVL72、スケーラブルユニット、逸脱のリスク
2. ネットワークを 4 系統で設計する — ibnet / internalnet / externalnet / ipminet、レール最適化、IB か RoCE か
3. 設置前に決めること — 三相での給電計算、空冷の限界と液冷、床荷重、搬入経路
4. ソフトウェアスタックを積む順番 — ドライバ、Fabric Manager、DOCA、Container Toolkit、NGC
5. 受け入れ検証 — DCGM diag、nccl-tests の busbw、ibdiagnet、引き渡し前のチェックリスト
6. 運用に引き渡す — 監視項目、版を揃える、故障 GPU の交換、台帳

### 10. ミドルウェア（6 レッスン）

OS のリソース管理の上に乗るプロセスとして捉え直す。

1. ミドルウェアのプロセスモデル — epoll、fd 上限、エフェメラルポート枯渇
2. リバースプロキシの実運用 — タイムアウトの階層、バッファリング、ヘルスチェックの波及
3. PostgreSQL の運用 — 接続の重さ、チェックポイント、autovacuum、**XID 周回**
4. Redis とキャッシュ運用 — 単一スレッド、maxmemory-policy、BGSAVE の fork
5. 監視とオブザーバビリティ — カーディナリティ爆発、症状ベースのアラート、SLO
6. メッセージングと非同期処理 — パーティションと並列度、acks、consumer lag

### 11. 認証基盤 / PKI（6 レッスン）

オンプレで認証基盤を組むための知識。

1. 認証と認可の基礎 — AuthN/AuthZ、セッション vs トークン、パスワード保存
2. X.509 証明書と PKI — SAN、信頼の連鎖、失効の限界
3. 自己認証局の構築と運用 — ルート/中間の分離、**トラストストア配布**、ACME 自動更新
4. OAuth 2.0 と OpenID Connect — PKCE、ID/アクセストークンの使い分け、JWT 検証
5. オンプレ IdP の構築と LDAP 連携 — Keycloak、AD 連携、署名鍵ローテーション
6. サービス間認証と mTLS — クライアント証明書、K8s の Bound Token、短命な資格情報

### 12. GPU の使われ方 — 学習と推論（6 レッスン）

基盤の上で、利用者は実際に何を書き、何を実行し、何が出てくるのか。基盤側から使い方を想像できる粒度で扱う。

1. 学習ループの中で起きていること — 順伝播・逆伝播・更新、GPU メモリの内訳、MFU
2. GPU を増やすと何が変わるか — DDP・FSDP・テンソル並列・パイプライン並列と、それぞれの通信
3. チェックポイントの実物 — 何が入り、どう再開するか、保存の猶予時間
4. ファインチューニング — フル・LoRA・QLoRA で変わる GPU とストレージの要求
5. 推論 — 学習済みモデルが API になるまで、vLLM と KV キャッシュ
6. 学習から推論への受け渡し — 配布用の重み、シャード、LoRA の配り方、量子化
